Cancellation does not remove queued transport work.

Queue request→Keep capacity owned→ACK or discard

The waiting caller could cancel and release a permit while its request still occupied transport storage. The fix keeps that permit with the request until ACK or discard. A one-slot native socket regression fails on the original code and passes with the fix.

Terms explained

A short guide to the technical words.

Prefill and decode
Prefill processes the input prompt. Decode produces new tokens step by step. A change can help one stage and slow the complete request.
KV cache
Stored attention keys and values from previous tokens. Reusing them avoids repeated model work. The memory budget and cache identity must be correct.
FP8
An eight-bit floating-point format. It can reduce memory and change the available kernels. Lower precision alone does not guarantee faster requests or equal output quality.
CUDA graph replay
A saved sequence of GPU work can run again with less launch overhead. Buffers must keep valid contents and lifetimes across replays.
Kernel / component benchmark
A measurement of a selected operation. It excludes other request costs. Its percentage must stay attached to that measured boundary.
Offline full-model check
The model generates tokens without the complete network-serving stack. It is stronger than a helper check, but it is not a full HTTP load test.
Baseline and candidate
The baseline is the original selected code. The candidate contains the proposed change. Exact commits keep comparisons tied to the correct version.
Upstream ownership
A maintainer or existing PR may already address the cause. Research can supply evidence to that owner instead of opening a duplicate fix.

4. Startup and loading research

Real startup and FP8 baseline measurements

Qwen3.8-27B on two H100s took 252.18 seconds to become ready in one cold process and 104.82 seconds in a later process in the same container. Compiler files and model-file cache state both changed. The 58.4% difference is a cold/warm observation, not a patch result. Steady decode matrix work accounted for about 83–84% of summed GPU kernel time in the tested 8,192-token case. This did not prove a memory-bandwidth bottleneck.

FP8 was not uniformly faster. Single-request output rates improved by about 30.5–33.2% in the first allocation. The eight-request, 2,048-token case lost 12.7%, 14.3% and 12.5% across three allocations. Exact-workload traces linked the loss to large mixed-prefill row counts taking the SM90 swap-AB route when the row count was not divisible by four. Steady decode could be faster while the complete request was slower. The small math checks had equal aggregate scores but different outputs; they do not establish equal model quality. Existing PR #60464 already addresses the measured dispatch rule. This audit reproduced the stock failure. It did not rebuild or validate that PR's fix.

Source: two-GPU profile.

Compiler work: useful attribution and rejected shortcuts

A later cold trace found 130 compile-adaptor attempts per rank, but only 40 reached native inner compilation. Ninety already took the reuse path. It did not prove 130 repeated full compilations. A 21–22 second region inside the PyTorch compiler frontend remained unattributed. It was a useful next target, not a completed optimization. Inclusive call durations and concurrent rank times must not be added.

Shared AOT artifact serialization was implemented and tested on two model families. Exact object memoization plus a content pool reduced native serialize calls from 29 to three and 27 to three. Artifact collection saved 49.54–56.06 ms. Fresh AOT cache loads matched all 64 generated tokens and returned logprobs. The collector still hashes all entries. Its whole complexity did not become constant per distinct object. The patch stays local at 6360d59e; it is held because a roughly 50 ms phase saving did not establish a useful startup gain.

Host-local checkpoint prefetch was rejected for submission. A two-host cache simulation improved page coverage from 50% to 100%, but did not show a speed gain. The loading ranks for an auxiliary model can differ from host membership. A new loader collective could wait for ranks that never enter that load. Existing pre-sharded loading and lazy views also disproved some simple copy assumptions.

The later compiler frontend trace attributed about 9.2 seconds to functional graph capture/cleanup and 5.6 seconds to mutation/view metadata. It still did not establish a safe removal. The earlier unattributed interval is a historical measurement, not the final limit of the investigation.

Sources: compiler audit, later frontend attribution, startup decision.

Graph-memory accounting correction

The warm graph estimate of 708 MiB and final capture delta of 74 MiB initially looked like a large avoidable gap. Explicit boundaries found 624 MiB retained after the temporary probe. Most of the apparent gap was not free memory that could safely become KV cache. Existing upstream work covered the confirmed accounting defects. No new broad graph-probe removal patch was justified.

Source: generic startup audit.

6. Full-model work from the cross-project chat

Grammar-selected output head

The experimental head projects the union of grammar-allowed vocabulary rows, then retains the normal mask, processors and sampler. It has no persistent selected-weight cache. Wide or unsupported batches use the dense path. The final patch profiles its maximum workspace before KV sizing and uses dense fallback with explicit manual KV budgets.

On Qwen3-4B, one L4, BF16, MRV2, TP1 and the recorded graph settings, three tested narrow workloads used 8.2–8.9% less complete offline request time. The unconstrained control had no clear change. Eighty-two final native tests and 16 full-model comparisons passed. The frozen 32-question JSON check had 32 valid objects and 10 correct answers on both paths. This is not a full GSM8K result or universal numerical identity.

An early BF16 projection changed two token sequences. The final FP32 selected projection fixed the observed failure. Startup memory was also repaired and retested. Those corrections are part of the final draft, not optional future work. TP, quantized heads, LoRA, speculation and broad serving are outside its support. This is the strongest measured model-speed draft in the records.

MLA request-table reuse

The Triton MLA draft stops copying a request block-table row for each draft query. Query rows index the original request table. It removes an O(BQW) temporary and copy; it does not remove attention arithmetic.

Full DeepSeek-V2-Lite-Chat used all 27 attention layers and accepted 3,650 draft tokens. Five full-model token/logprob comparisons matched. Metadata, native attention and changed-page graph checks passed. Full-model timing was noisy and mixed. No stable full-model speedup is established. It remains an allocation-reduction draft.

Source for both: final grammar and MLA review. Earlier overnight results are superseded where the later review repaired precision, memory or test coverage.

N-gram replay: a useful negative result

A large isolated host/launch gain did not justify a broad model-speed claim.
