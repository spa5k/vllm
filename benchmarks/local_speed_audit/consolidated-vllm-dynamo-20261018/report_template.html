What changed

The results in plain language.

Correctness and performance need different proof. These examples show the cause, the change and the limit of the evidence.

vLLM · Memory safety · Open PR

A saved plan must use the current memory budget.

16.15 → 6.23 GiB
Stale KV allowance → freshly profiled allowance in the tested budget change

A startup plan can outlive the settings that produced it. After the GPU budget fell, the old plan still allowed too much KV memory. The fix invalidates that plan. Related work adds multimodal inputs to the plan identity.

This is a correctness result. It is not 9.92 GiB of memory saved in a normal unchanged run. The PT loader separately reduced tracked live-tensor peaks by 52–59%; RSS/PSS did not show a clear reduction.
Dynamo · Transport correctness · Draft PR

Cancellation does not remove queued transport work.

Queue request→Keep capacity owned→ACK or discard

The waiting caller could cancel and release a permit while its request still occupied transport storage. The fix keeps that permit with the request until ACK or discard. A one-slot native socket regression fails on the original code and passes with the fix.

The combined native network run passed 304 cases with three known base cases excluded. This is not a complete clean network-suite result or a model-speed result.
vLLM · Offline model result · Local draft

Small grammar vocabularies can avoid a full projection.

8.2–8.9% less time
Complete offline request time · three narrow Qwen3-4B workloads · one L4

A grammar can permit only a small set of next tokens. The draft projects those rows, then keeps the normal mask and sampler. The final version repairs observed precision and startup-memory problems. It is off by default.

BF16, TP1, MRV2 and the recorded graph settings. Broad grammars and unsupported modes fall back. This does not establish a general serving gain or equal accuracy on a large benchmark.
vLLM + Dynamo · Failure handling · Drafts

Follow each operation to its terminal state.

Some failures occur after the function that created the operation has returned. The later vLLM drafts cover a missed KV rejection notice, utility calls left pending after engine death and background Responses left queued after an error.

Dynamo also has a four-file metadata fix. List and retrieve used different projections for the same model. A normal Rust regression fails on the baseline and all five selected candidate tests pass.

The vLLM lifecycle suites use mocked engine or transport boundaries. Live connector, engine and public HTTP checks remain. The Dynamo metadata gate is distinct from an inference test.

A faster component can leave the whole request unchanged.

N-gram graph replay reduced isolated proposer time by 68.9–71.0%. The later Qwen3-4B run matched 69,003 timed tokens per arm, but full-generation medians were 0.01–0.02% slower. The draft stayed on hold. Fusion saved metadata microseconds. FP8 scratch reuse saved a 4 MiB temporary in one tested fallback shape. Each claim keeps its actual boundary.

Read the evidence correctly

What each test can establish.

These categories describe different boundaries. More test cases do not turn a source check into a model result.

Source / mocked

Does the contract make sense?

Source review and controlled fixtures can expose a wrong state or missing call. They do not prove actual GPU or network behavior.

Normal project suite

Does the project regression pass?

Normal imports, dependencies and fixtures exercise the selected suite. Its mocked boundaries and skipped cases still matter.

Native component

Does the actual component work?

A real kernel, socket, broker or native library runs. Its result does not automatically cover the complete serving path.

Full model

Does the tested model path agree?

Tokens, scores and complete request time can be checked. Synthetic models, narrow prompts and offline runs retain those limits.

Terms explained

A short guide to the technical words.

Prefill and decode
Prefill processes the input prompt. Decode produces new tokens step by step. A change can help one stage and slow the complete request.
KV cache
Stored attention keys and values from previous tokens. Reusing them avoids repeated model work. The memory budget and cache identity must be correct.
FP8
An eight-bit floating-point format. It can reduce memory and change the available kernels. Lower precision alone does not guarantee faster requests or equal output quality.
CUDA graph replay
A saved sequence of GPU work can run again with less launch overhead. Buffers must keep valid contents and lifetimes across replays.
Kernel / component benchmark
A measurement of a selected operation. It excludes other request costs. Its percentage must stay attached to that measured boundary.
Offline full-model check
The model generates tokens without the complete network-serving stack. It is stronger than a helper check, but it is not a full HTTP load test.
Baseline and candidate
The baseline is the original selected code. The candidate contains the proposed change. Exact commits keep comparisons tied to the correct version.
Upstream ownership
A maintainer or existing PR may already address the cause. Research can supply evidence to that owner instead of opening a duplicate fix.
