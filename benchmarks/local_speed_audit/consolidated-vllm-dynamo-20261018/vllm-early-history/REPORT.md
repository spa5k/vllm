## Startup, compiler and whole-engine profiling

### 8 October: measure before making a generic speed claim

Qwen3.8-27B BF16 TP2 on two H100 80 GB GPUs used native wheel `e572e02d21b2b3559b3ce33adb117dca3f50ccd7`. First and second process-to-ready times were 252.18 and 104.82 seconds. Cold/warm cache state changes several stages. This is a configuration profile, not a patch comparison. The ordinary offline BF16 rates include 80.79 output tokens/s at 128×1 and 420.98 at 2048×8. They exclude network serving and input tokenization. [Environment and startup](/Users/pacific/Developer/vllm/benchmarks/local_speed_audit/two-gpu-profile-20261008/REPORT.md:17), [request boundary](/Users/pacific/Developer/vllm/benchmarks/local_speed_audit/two-gpu-profile-20261008/REPORT.md:53).

The selected long decode windows place 83.1–84.3% of summed GPU kernel time in matrix work. Communication is 6.9–7.9%; Gated DeltaNet/convolution and full attention are smaller shares. A later saved-trace review finds about 4% of the selected long-context timeline without traced GPU activity. The denominators differ. Neither proves memory-bandwidth saturation or a general CPU bottleneck. [Kernel attribution](/Users/pacific/Developer/vllm/benchmarks/local_speed_audit/two-gpu-profile-20261008/REPORT.md:69), [corrected timeline boundary](/Users/pacific/Developer/vllm/benchmarks/local_speed_audit/core-radical-20261015/REPORT.md:144).

Online block FP8 with CUTLASS fallback gives 30.5–33.2% higher single-request output rates in the first paired allocation. The short case repeats at +31.4%. Eight-request rates regress in three paired allocations by 12.7%, 14.3% and 12.5%. Exact traces identify large mixed-prefill rows 2049 and 4103 taking the stock swap-AB dispatch route. Existing **#60464** already fixes that rule. The audit confirms the stock failure, not the PR's fixed speed. DeepGEMM was disabled because the image lacked the CUDA toolkit. All five 32-question math diagnostics scored 30/32, but truncation and wrong-answer patterns differ; equal scores do not establish equal accuracy. [FP8 comparison](/Users/pacific/Developer/vllm/benchmarks/local_speed_audit/two-gpu-profile-20261008/REPORT.md:143), [duplicate dispatch fix](/Users/pacific/Developer/vllm/benchmarks/local_speed_audit/two-gpu-profile-20261008/REPORT.md:167).

The initial graph-memory gap was corrected. Warm probe-retained device memory was about 624 MiB. It is not all free capacity for KV cache. Negative graph samples of −20/−18 MiB repeat on both ranks, but existing **#59368** and adjacent work already cover the accounting paths. No duplicate graph-accounting PR was prepared. [Correction](/Users/pacific/Developer/vllm/benchmarks/local_speed_audit/generic-startup-audit-20261008/REPORT.md:46).

### Artifact serialization and checkpoint prefetch

The compiler artifact collector serializes aliased native artifacts before byte deduplication. A two-production-file plus existing-test-file draft memoizes exact native identities per collection and pools equal payload bytes. Final commit: `6360d59eb9a534cb995069523de9293f201e5e80`, branch `feat/memoize-shared-compiled-artifacts`. Qwen3-0.6B collection changes 116.63 to 67.08 ms; Ministral-3-3B changes 115.07 to 59.02 ms. Serialize calls change 29→3 and 27→3. Both changed caches load in fresh processes and match all 64 generated tokens and reported logprobs. The initial memo's duplicate-buffer retention was fixed. The draft stays on hold: 50–56 ms of collection saving does not establish useful total startup gain. [Final serialization decision](/Users/pacific/Developer/vllm/benchmarks/local_speed_audit/generic-startup-audit-20261008/final-validation/REPORT.md:5).

Checkpoint controls find no reliable benefit from replacing `get_tensor()+narrow()` with `get_slice()`. The existing pre-sharded loader reduces one CPU copy fixture from 240.15 to 164.38 ms; enabling an existing feature is not a new code contribution. Host-local prefetch improves simulated page-cache coverage from 50% to 100%, but has no measured startup gain. It is rejected: host membership does not identify load participants, PP draft loading can use a subset, file lists differ, and loader collectives can deadlock. A safe fix would need a broader participant contract. [Loading controls](/Users/pacific/Developer/vllm/benchmarks/local_speed_audit/generic-startup-audit-20261008/REPORT.md:67), [final prefetch rejection](/Users/pacific/Developer/vllm/benchmarks/local_speed_audit/generic-startup-audit-20261008/final-validation/REPORT.md:51).

### Compiler frontend attribution and rejected shortcuts

The direct timer shows 130 adaptor attempts per rank: 40 compile and 90 exit through intended reuse. The latter total about one second. A 21–22 second previously unassigned `compile_fx` region is not duplicate full compilation. A later bound-alias trace attributes about 9.2 seconds to functional graph capture/cleanup and 5.6 seconds to mutation/view metadata. No safe removal is proved. Near-linear FX placeholder normalization, graph donation already enabled, native kernel caches, and proper mutation barriers reject several broad shortcut ideas. **#53892**, **#39535**, and PyTorch **#192047** cover nearby existing fixes. Pass hashing already has a cache, lazy graph logging is not eager formatting, and no measured harmful superlinear cost was shown for the other passes.
